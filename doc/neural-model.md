# Modèles neuronaux locaux

Le pack public courant utilise [CamemBERTv2](https://huggingface.co/almanach/camembertv2-base) sous licence MIT. Son vocabulaire WordPiece comporte 32 768 jetons, avec `[MASK]` = 4 et `[PAD]` = 0. Le moteur accepte également les anciens packs SentencePiece de 32 005 jetons. Les champs optionnels `maskTokenId` et `padTokenId` de leur `model.json` décrivent ces identifiants ; leur absence conserve les valeurs v1. `floatActivations: true` conserve les activations en flottants lors des produits avec les poids int8 ; son absence conserve le calcul v1. Ce modèle lexical public et son tokenizer restent indépendants des quatre fichiers d’un modèle grammatical importé décrits ci-dessous.

Dans les paramètres de Finition, **Corrections** présente Grammalecte avec son choix **Classique** ou **Réforme 1990**. Cette même section contient **Correcteur neuronal par défaut**, vide avant installation, puis **CamemBERT** à charger depuis GitHub et les modèles grammaticaux locaux affichés sous leur nom. Le choix automatique existant affiche le nom du modèle réellement choisi. Sélectionner un modèle active ses corrections sans interrupteur supplémentaire. Les modèles grammaticaux utilisent les ressources communes de CamemBERT ; sans ces ressources, un modèle importé reste dans la liste mais ne peut pas être lancé.

Sous les ressources publiques, chaque modèle local affiche son `name`, sa `description` facultative et **Effacer**. Si `documentation` contient une URL HTTP ou HTTPS, la description devient cliquable ; sans description, le lien affiche **Documentation**. Sans URL, aucun lien n’est ajouté. Effacer demande confirmation et supprime uniquement le dossier de ce modèle dans le plugin. Si le modèle était actif, Finition revient à **CamemBERT**, sans modèle grammatical spécialisé.

## Installer un modèle

Sous la liste des modèles, **Charger un modèle neuronal** accepte le chemin du dossier ou de son `pack.json`. Un chemin relatif désigne un dossier du coffre ; un chemin absolu peut désigner un dossier ailleurs sur la machine, notamment dans un autre coffre. Les fichiers externes sont lus uniquement lors du clic sur **Charger**, avec l’API Obsidian. **Parcourir…** ouvre le sélecteur système pour choisir le dossier complet du modèle, y compris dans un autre coffre. Sur macOS, **⌘⇧.** permet d’afficher les dossiers cachés comme `.obsidian` ; l’API publique Obsidian ne permet pas de forcer leur affichage. Si le champ reste vide, **Charger** ouvre aussi ce sélecteur. Le dossier doit contenir `pack.json` et les quatre fichiers de données listés ci-dessous. Finition vérifie leurs tailles et empreintes SHA-256 et les copie dans `Antidote/models/<empreinte-du-catalogue>/`, le stockage local privé déjà ignoré par Git ; la source reste intacte. Les autres fichiers du dossier source, notamment les checkpoints Python, ne sont pas importés. Un import incomplet ou altéré conserve le choix précédent. Réimporter le même catalogue ne crée pas de doublon. Les poids se chargent pour l’analyse seulement à la première utilisation ; l’import les lit pour contrôler leur intégrité. Changer de modèle arrête ses Workers et efface les suggestions précédentes.

L’ajout manuel dans `scripts/neural/models/<identifiant>/` reste possible, avec un identifiant composé de lettres ASCII, chiffres, traits d’union ou tirets bas ; recharger le plugin pour redécouvrir ces dossiers.

Les modèles restés dans l’ancien dossier `helper/neural/models/` restent reconnus. Lorsqu’un modèle sélectionné est déplacé dans `scripts/neural/models/`, son nouveau chemin est enregistré automatiquement au rechargement.

Le dossier privé `Antidote/model/` suit le même format. Il est ignoré par Git, réservé aux ressources locales et exclu des packs de téléchargement. Le choix automatique existant utilise ce modèle privé s’il est présent, sinon le premier modèle compatible de `scripts/neural/models/`, puis de `Antidote/models/`, triés par identifiant dans chaque dossier. Le choix **CamemBERT** désactive le complément grammatical spécialisé. Un modèle explicitement sélectionné puis retiré produit une erreur ; il n’est pas remplacé silencieusement.

Un dossier de modèle contient `pack.json`, `electra/model.json`, `electra/weights.bin`, `electra/tokenizer.json` et `electra/labels.json`. Le catalogue contient `version: 1`, `architecture: "finition-electra-v1"`, un `name` de 1 à 80 caractères et une liste `files`. Les champs facultatifs `description` (texte simple de 1000 caractères maximum) et `documentation` (URL HTTP ou HTTPS de 2000 caractères maximum) fournissent les métadonnées affichées ; les caractères de contrôle sont refusés. Chaque entrée contient `path`, `bytes` et `sha256`, une empreinte SHA-256 hexadécimale minuscule. Les quatre chemins de données sont imposés ; aucun script ou runtime ne peut être ajouté. Les tailles sont contrôlées pendant la découverte, puis les empreintes lors du chargement. Les checkpoints Python ne font pas partie de ce catalogue.

## Profil finition-electra-v1

Le format conserve l’architecture prise en charge par le moteur existant. Il ne transforme pas les poids d’une architecture différente. La définition TypeScript des tenseurs est `ModelData` dans [model.ts](../plugin/modes/finition-corrector/model.ts), avec `version: 1` et `kind: "electra"`.

L’encodeur possède un vocabulaire de 32005 entrées, des embeddings de largeur 128, 512 positions, 2 types de jetons, une projection vers 256 dimensions, 6 couches Transformer et 4 têtes d’attention. Le bloc intermédiaire possède 1024 dimensions et une activation GELU. Les normalisations utilisent leur epsilon enregistré dans `model.json`. Les positions commencent à zéro ; les types de jetons sont tous zéro. Les identifiants imposés sont `<pad>` = 1, `<unk>` = 3, `<s>` = 5 et `</s>` = 6. Les fenêtres grammaticales sont encadrées par 5 et 6 ; leur contenu comprend au plus 128 sous-jetons.

Chaque classifieur suit `Linear(256,128) → ReLU → Linear(128,128) → LayerNorm(128) → ReLU → Linear(128,n)`. Les sorties sont les suivantes :

| Nom | Classes | Interprétation |
| --- | ---: | --- |
| `VirguleManquanteGeneraleDevant` | 2 | `O`, puis virgule avant le mot |
| `MotsManquantsGeneralDevant` | 125 | `O`, puis mot ou élision à insérer avant le mot |
| `est` | 12 | `O`, puis graphies de la famille est/et |
| `ou` | 3 | `O`, puis graphies de la famille ou/où |
| `ces` | 5 | `O`, puis graphies de la famille ces/ses |

`labels.json` contient ces cinq listes, dans l’ordre exact des logits du modèle. L’index zéro désigne toujours `O`, aucune correction. La liste des virgules est exactement `["O", ","]`. Les classes textuelles et le tokenizer appartiennent au modèle ; entraîner un modèle exige ses propres données et annotations, pas les poids privés.

Les tenseurs de `weights.bin` sont décrits par `{offset, dims, type}` : offset en octets, dimensions en ordre ligne, type `f32`, `i8`, `u8` ou `i32`. Les nombres de plusieurs octets sont little-endian et alignés sur quatre octets. Une matrice dense utilise `[sorties, entrées]`, son biais `[sorties]`. Les embeddings indiquent une échelle et un zéro ; une valeur se décode par `(valeur - zéro) × échelle`. L’export Python écrit exclusivement du float32, sans quantification. Le lecteur conserve aussi les types du format historique ; il ne requantifie pas les poids privés.

## Exploiter et évaluer un modèle

Les cinq sorties spécialisées couvrent les mots manquants, les virgules et trois familles d’homophones. Elles ne constituent pas une analyse syntaxique générale : elles ne prédisent pas directement les accords arbitraires, les rattachements de participes ou toutes les confusions lexicales. Finition combine ces sorties avec ses règles morphologiques et les propositions lexicales de CamemBERT ; sélectionner un modèle ne remplace pas ces étapes par le correcteur complet dont ce modèle pouvait être un composant.

La couche syntaxique embarquée en TS est indépendante des poids et utilise le même dictionnaire morphologique. Elle regroupe les noms avec leurs déterminants, adjectifs et compléments en « de », distingue les verbes conjugués des infinitifs et participes, puis relie les sujets et compléments aux verbes. Les constructions verbales prises en charge sont énumérées dans `plugin/modes/finition-corrector/syntax.ts` ; cette liste reste partielle. Les ambiguïtés nominales et les majuscules interviennent avant la génération des alertes, pour éviter notamment de lire « Marie » comme le verbe « marier ».

Les diagnostics `ponctuation.sujet-verbe`, `ponctuation.verbe-complement` et `ponctuation.complement-infinitif` proposent de retirer une virgule qui coupe une relation grammaticale identifiée. `ponctuation.interrogation` propose une espace insécable suivie de `?` pour certaines questions directes : mots interrogatifs, inversions et constructions en « est-ce que ». Les titres Markdown, titres cités, interrogations indirectes et formulations déclaratives repérées sont exclus. Les relations de virgule sont laissées sans alerte quand la phrase contient plusieurs virgules : incises, appositions et énumérations nécessitent une analyse des subordonnées plus complète. Les groupes nominaux imbriqués sont limités à neuf niveaux ; les questions contenant un autre verbe conjugué après le prédicat restent généralement sans alerte. Cette première couche ne reconstitue pas un analyseur grammatical français complet et n’effectue aucun classement statistique des arbres possibles.

Ces corrections sont proposées à validation par le correcteur **Neuronal**, avec CamemBERT comme avec un modèle spécialisé importé. La commande typographique **Ponctuations** conserve son rôle de normalisation des espaces, apostrophes et tirets.

Les règles `accord.quantite`, `accord.adjectif` et `verbe.infinitif-coordonne` complètent les accords locaux. Les unités de quantité connues gouvernent le pluriel de leur complément (« un millier de phrases »), et leur emploi sans déterminant après « de » appelle le pluriel (« de dizaines de milliers »). L’accord de l’adjectif est également vérifié sans article et après les adverbes de degré (« résultats moins bons »), en conservant les rattachements possibles aux noms des groupes parents. Les lectures concurrentes de verbe conjugué restent sans nouvelle alerte d’adjectif.

Un participe passé coordonné à un infinitif sous un verbe régissant explicite peut être remplacé par l’infinitif de son lemme (« il faut créer…, puis entraîner un modèle »). Cette règle exige soit un infinitif immédiatement avant la coordination, soit un objet nominal après le participe. Elle s’abstient notamment avec un auxiliaire partagé, un nouveau sujet ou une durée, pour préserver les participes et les modificateurs de noms. Les subordonnées et changements de proposition peuvent interrompre cette analyse ; sa couverture reste partielle. Aucun poids ni dictionnaire supplémentaire n’est requis pour ces règles.

Le décodeur applique une politique distincte par sortie : classe gagnante pour `est` et `ces`, probabilité d’au moins 0,84 pour la proposition `où`, 0,95 pour les insertions de mots et de virgules. Une proposition qui remplace seulement `ces` par `ses`, ou inversement, est écartée : ces deux déterminants peuvent désigner des référents différents dans une phrase grammaticalement correcte. Les seuils d’insertion restent prudents ; ils ne reproduisent pas les arbitrages syntaxiques d’un autre moteur. Les scores softmax ne constituent pas une mesure validée de la probabilité qu’une correction soit juste.

Les positions restent exprimées en unités UTF-16 du texte original, après normalisation pour le tokenizer. Un homophone peut commencer après une élision, comme `est` dans `J’est` : remplacer le mot composé entier perdrait le préfixe. Chaque test vérifie que la plage affichée correspond exactement au texte remplacé. Les noms de sorties, les classes et les conventions de tokenisation doivent rester compatibles avec le profil ; changer seulement les poids ne change pas la couverture du moteur. Lorsque le complément spécialisé est désactivé, les paires `et/est` et `ou/où` restent examinées par CamemBERT.

CamemBERT évalue aussi les phrases de deux ou trois mots. Ses candidats sont tokenisés dans leur contexte complet : l’identifiant de `a` après `n’` peut différer de celui de `a` isolé. Le moteur ne compare que des candidats remplaçant exactement un jeton masqué, avec tous les autres identifiants inchangés ; les propositions nécessitant plusieurs sous-jetons restent hors de cette méthode. Le préfixe élidé est conservé dans le texte et dans le contexte soumis au réseau.

Pour les prochains modèles, vérifier séparément la fidélité numérique à l’export de référence, le rappel sur des erreurs annotées, les fausses alertes sur des textes corrects et la durée avec puis sans cache. Conserver des exemples avec élisions, Unicode décomposé, emojis, longues phrases, Markdown et choix sémantiques ambigus. Le test ciblé `scripts/check-finition-electra.ts` constitue une régression locale, pas un benchmark général ni une comparaison de qualité avec un autre correcteur. Toute extension à l’analyse syntaxique ou aux corrections de plusieurs mots doit disposer de ses propres annotations et sorties prises en charge.

## Entraîner un modèle indépendant

[scripts/neural/train.py](../scripts/neural/train.py) entraîne un nouveau modèle depuis une initialisation aléatoire, sans lire le modèle privé et sans téléchargement implicite. Il peut être exécuté sur une machine équipée de PyTorch, Transformers, Tokenizers, NumPy et Safetensors, y compris un environnement de calcul Hugging Face. Il utilise CUDA si disponible, sinon le CPU ; le chemin CUDA n’a pas été vérifié sur cette machine Mac. Python sert à l’entraînement et à l’export ; le plugin utilise uniquement les quatre fichiers de données et son moteur embarqué.

Préparer un tokenizer compatible de 32005 identifiants, ses cinq listes de classes et deux corpus JSONL distincts. Chaque ligne contient `input_ids`, une liste de 3 à 130 identifiants commençant par 5 et finissant par 6, et `labels`, un objet contenant les cinq listes d’indices de classes. Chaque liste a la longueur de `input_ids`. Utiliser `-100` pour les jetons ignorés, dont les deux bornes, `0` pour les positions correctes, et l’indice de la correction attendue aux positions fautives. Annoter le premier sous-jeton du mot, utilisé par l’affichage du correcteur ; ignorer ses autres sous-jetons. Inclure suffisamment de phrases correctes pour mesurer les faux positifs. Le script refuse les doublons et les séquences communes aux corpus d’entraînement et de validation.

Invocation avec des données à fournir, non exécutée comme entraînement de production :

```bash
python scripts/neural/train.py --train corpus/train.jsonl --valid corpus/valid.jsonl --tokenizer corpus/tokenizer.json --labels corpus/labels.json --output scripts/neural/models/mon-modele --name "Mon modèle" --epochs 3
```

Le dossier de sortie doit être nouveau. Le script affiche la perte de validation après chaque époque, puis écrit un pack sélectionnable et un checkpoint `training.safetensors`. La qualité d’un modèle nouvellement initialisé dépend du volume et de la qualité du corpus ; un entraînement court ne fournit pas un correcteur utilisable. Les seuils prudents de Finition restent ceux du moteur existant et doivent être évalués sur un corpus représentatif, notamment pour les faux positifs.

## Vérifier la compatibilité

`scripts/neural/check.py` effectue un pas d’entraînement indépendant, vérifie les annotations et exporte les scores de référence PyTorch. Il reçoit le tokenizer, les classes et un nouveau dossier de sortie. `scripts/check-trained-model.ts` recharge cet export dans le moteur TS et compare ses scores à la référence avec une tolérance absolue de 0,001. Ces contrôles prouvent le chargement et la fidélité numérique des exemples ; ils ne mesurent pas la qualité linguistique générale.

Le contrôle `scripts/check-finition-model.ts` compare séparément les modèles locaux existants à leurs sources ONNX, sans modifier leurs fichiers. Le test navigateur `scripts/check-tic-click.ts` couvre les changements de modèle, leur persistance, la désactivation, les fichiers altérés et l’exclusion des poids privés du catalogue public.
