# Correction locale

Dans Réglages → Finition → Orthographe, télécharger les ressources « Neuronal ». Le téléchargement installe le dictionnaire morphologique, les données phonétiques, les poids de CamemBERT et du modèle spécialisé ELECTRA. Aucun code ni runtime ne fait partie du téléchargement. Il sélectionne ce moteur et active « Correction contextuelle locale ». Sans ressources, Grammalecte, Neuronal, Tricolons et Structure restent grisés. Les anciens packs neuronaux doivent être préparés dans le nouveau format ou téléchargés à nouveau. Dans le menu ♫, Grammalecte et Neuronal lancent directement la correction ; les moteurs absents sont grisés et Neuronal active les modèles locaux. Le choix Corrections IA de cette section traite la sélection avec le fournisseur configuré. Recliquer sur un correcteur coché retire ses suggestions.

Les groupes phonétiques sont filtrés avec les lemmes, rôles et fréquences du dictionnaire, chargé une seule fois. Une lecture grammaticale dominante écarte le mot des comparaisons lexicales ; une lecture rare sans fréquence ne masque pas un nom ou adjectif attesté. CamemBERT compare des noms et adjectifs de lemmes distincts, dont plaine/pleine, avec genre et nombre compatibles. Il préserve les flexions d’un même lemme et les mots grammaticaux ; les familles a/à, son/sont, on/ont, sa/ça et ce/se sont conservées explicitement. Les candidats compatibles avec un seul sous-jeton sont regroupés entre paragraphes et triés par longueur avant analyse par lots de quatre, afin de réduire le remplissage et les petits lots. Une proposition demande un rapport de vraisemblance de 10:1 ; ce rapport n’est pas une probabilité de faute calibrée. Les mots composés sont préservés. CamemBERT reste un modèle général, sans entraînement supplémentaire à la correction.

ELECTRA utilise les poids locaux complets du modèle choisi dans les paramètres, avec cinq sorties : virgules, mots manquants et familles est/ou/ces. Son tokenizer et ses classes accompagnent ses poids. Les packs locaux et leur entraînement sont décrits dans [le format neuronal](../../../doc/neural-model.md). Les suggestions privilégient les scores élevés, avec des seuils propres à Finition ; elles ne reproduisent pas les arbitrages d’un autre logiciel. Ce modèle ne couvre pas seul les confusions lexicales comme plaine/pleine. Sans modèle spécialisé, CamemBERT reste actif pour les confusions lexicales.

Le calcul CamemBERT conserve les poids et le calcul contextuel ; la projection finale ne calcule que les candidats comparés au mot masqué. Ses paragraphes sont répartis entre quatre Workers maximum selon les cœurs disponibles et le nombre de candidats ; aucun modèle général ne se charge quand le texte ne contient aucune confusion admissible. Cela consomme davantage de mémoire pendant l’analyse ; les sessions et les caches sont conservés jusqu’à l’arrêt du moteur. Les premières corrections orthographiques apparaissent avant la fin des modèles, qui complètent ensuite les suggestions. Une roue accompagne le message « Correction neurale » pendant le traitement.

Les règles d’accord restent prudentes devant une lecture possible de préposition ou de conjonction et reconnaissent les nombres composés terminés par un ou une. Les verbes avec pronoms reliés par un trait d’union sont reconnus à partir de leurs flexions, avec contrôle de la personne en inversion, de la liaison et de l’impératif. Après un complément prépositionnel, un adjectif compatible avec le nom principal n’est pas signalé fautif au seul motif qu’il ne s’accorde pas avec le nom voisin. Ce contrôle reste local et ne remplace pas une analyse complète des dépendances. Le correcteur ne déduit pas le genre du destinataire à l’échelle du document.

Le texte reste dans des Workers locaux. Leurs requêtes réseau sont bloquées ; les poids, les descriptions numériques et le vocabulaire passent par l’adaptateur de fichiers du coffre. Aucun serveur ni Python nécessaire à l’utilisation. Le modèle se charge à la première analyse avec l’option activée et reste en mémoire jusqu’à l’arrêt du moteur ou du plugin. Désactiver l’option suspend ses propositions. Les paragraphes inchangés de l’analyse précédente sont réutilisés. Les positions UTF-16, la sélection et la protection Markdown suivent le moteur existant.

Les dictionnaires et métadonnées de `resources/` et les poids publics de `scripts/neural/camembert/` sont distribués séparément de main.js. `npm run resources -- /chemin/de/destination` prépare les fichiers plats et les catalogues SHA-256 des moteurs. Les modèles spécialisés locaux sont exclus de cette préparation. Seules les ressources publiques sont jointes à la release portant exactement la version du plugin ; `release.sh` inclut leur préparation dans sa publication. L’activation intervient après vérification du téléchargement complet ; un échec conserve l’installation précédente. Les scripts des moteurs restent livrés dans main.js. Le calcul neuronal utilise `model.ts` et un petit noyau de produits scalaires SIMD assemblé par `matrix.ts` à partir des instructions livrées avec le plugin. Aucun binaire WASM externe n’est lu ou téléchargé. Les scores ne sont pas identiques à ceux d’ONNX Runtime : les tests vérifient les décisions lexicales et les corrections du corpus local, sans constituer une validation de précision générale.

Pour préparer les données CamemBERT : `npx --no-install jiti scripts/prepare-finition-neural.ts`. Cette préparation utilise Internet. Pour les poids spécialisés : `npx --no-install jiti scripts/prepare-finition-electra.ts modele.onnx vocabulaire.psi types.psi`, avec les fichiers locaux correspondant aux empreintes attendues. La conversion `scripts/convert-finition-models.ts` extrait les poids des modèles locaux et les range dans des tableaux binaires avec une description JSON ; aucun opérateur exécutable ne provient des fichiers téléchargés.

Les données phonétiques proviennent de Grammalecte. Les notices accompagnent les ressources. Aucune licence ouverte de redistribution n’a été identifiée pour les poids spécialisés importés et les formes complémentaires du dictionnaire.

Vérification : `npm run build`, `npm run lint`, puis `npx --no-install jiti scripts/check-tic-click.ts`. Le navigateur charge les ressources locales réelles avec le réseau coupé, vérifie des corrections, des phrases correctes, les offsets, la sélection, le cache, la désactivation, le redémarrage et l’absence de fichier. Ces exemples ne constituent pas une mesure de précision sur un corpus représentatif.

Mesure sur un document local : `npx --no-install jiti scripts/check-finition-performance.ts /chemin/du/texte.md`. Le test utilise les Workers et le calcul intégré du moteur, vérifie les positions, la stabilité des résultats au second passage et un budget de 40 secondes. Il mesure aussi le délai des premières corrections et affiche les durées et les empreintes sans afficher le texte.

Contrôles numériques : `npx --no-install jiti scripts/check-finition-matrix.ts` vérifie les produits scalaires et les projections. `npx --no-install jiti scripts/check-finition-model.ts` compare les scores ELECTRA et les décisions CamemBERT à une référence ONNX locale ; ce contrôle de développement nécessite les fichiers ONNX sources et le runtime déjà fourni dans node_modules, qui ne sont pas distribués par les packs.
